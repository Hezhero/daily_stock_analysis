## Comments

- **裁决来源**：2026-11-18 设计轮。提问为「缓存保留如何处置 J1 的跨口径互删」，给出三个选项
  （A 按完整后缀分组各留 1 / B 只清理当前运行的口径 / C 不改、仅文档提醒）；用户在后续轮次进一步
  明确为「**不分组，按 mtime 保留最新 1 个**」——即行为与票 01 现状一致，故本票零代码改动。
- **为什么不选分组**：分组需要在 `cleanup_prepared_cache` 里解析文件名后缀作为分组键，并回答
  「`keep` 是每组 N 个还是总数 N 个」——两个语义都会让参数更难解释；而全局 1 个已经消除了
  13GB 累积的主诉求（票 01 实测 13.0GB → 785MB）。
- **与票 01 的关系**：票 01 交付「全局按 mtime 保留 N 个」的机制与测试；本票确认不扩展为分组。
  两票合起来构成「机制 + 边界裁决」的完整记录。
- **验证**：本票无代码改动，`py_compile` / 定向 pytest 不适用；治理检查 `check_ai_assets.py`
  与 `check_spec_tickets.py` 通过即视为交付完成。
